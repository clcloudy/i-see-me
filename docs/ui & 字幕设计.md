# UI 与字幕要求

风格：全 3D。**所有文字都放在场景里**，不平铺到视图上——不只是字幕，控制条、词条、卡片、分支选项、提示、
转场文字，凡是有字的地方都必须是三维空间里的字，而不是贴在屏幕上的 HUD。

## 一、总原则

1. **文字在世界里**：都占据三维坐标，随相机产生透视、近大远小与遮挡关系；不用 `CanvasLayer` + `Label/Button/RichTextLabel` 铺满视口做界面，也不用 `full rect` 的全屏 `Control` 当底板——界面是场景里的物件，不是叠在画面上的一层。
2. **有距离有体积**：文字面片与相机保持真实距离（约 0.4–2 m），可被场景中的物体挡住，也受教室的光影响；不受光时由材质自身给出明度，保证可读。
3. **可读优先**：全 3D 不等于牺牲可读性，字号、描边、底色板要保证在教室光照下看得清。

允许：`Label3D`（世界空间文字）、`Sprite3D` / `MeshInstance3D` 面片做底板与按钮；需要真正的输入控件时，用
`SubViewport` 把控件渲染到**世界空间的面片**上（面片仍在场景里，有距离与透视，不得铺满视口）；鼠标拾取用三维射线
（`Area3D` / `Camera3D` 投影），键盘快捷键照常可用。不允许任何"贴屏幕边缘/居中、不随视角变化"的文字。

## 二、覆盖范围（一处不落）

| 文字 | 位置 |
| --- | --- |
| 说话字幕 | 说话者头部旁/上方约 1.55 m，始终朝向相机 |
| 说话者名字 | 与字幕同处，不做单独的屏幕角标 |
| 控制条（跳过/暂停/静音/重开/退出） | 场景内的一排面片按钮，随视角有透视 |
| 品牌名（I See Me · 课堂对话） | 与控制条同一组，不贴屏幕边缘 |
| 词条 chip（第二层·某某感受） | 出现在事件发生处或视野一侧的世界空间面板 |
| 回答框（标题、一个输入框、提交） | 悬在玩家面前偏下的世界中，像举在手里的一块牌子 |
| 卡片（开场说明、暂停、完成、L2 词条） | 同分支选择，玩家面前的世界空间面板 |
| 转场文字（正在进入第二层…） | 世界空间，不贴在屏幕顶部 |
| 转头提示（拖动鼠标…） | 世界空间，出现在玩家视野下方，可淡出 |
| 玩家输入的回答回显 | 同上，属于世界空间面板的一部分 |
| 事件小球的标签、声纹旁的提示字 | 就地存在于三维空间 |

## 三、空间与朝向

- 字幕、事件标签：公告板朝向相机（`BaseMaterial3D.BILLBOARD_FIXED_Y`，只绕 Y 轴、保持直立），
  **不得用 `look_at` 手动朝向相机**（相机贴近锚点时会算出 NaN 变换导致闪退，见 `docs/3d-scene-ui.md`）。
- 卡片 / 选择面板：不公告板化，与相机保持固定相对姿态，**悬在玩家面前约 1.2 m**，
  像"举在面前的一块板"，轻微倾斜 5°–10°，避免正对时像截图。
- 面板之间的前后关系用真实距离表达，不用 UI 层级；近的面板挡住远的面板是正确表现。
- 所有尺寸以米为单位；文字在默认视距（约 1.2 m）下的视觉大小对齐现有 18–22 px 的观感。

## 四、交互

- 按钮 = 场景里的一块面片/物件，鼠标射线拾取；悬停有明度或描边变化，点击有下压反馈。
  面板出现/消失是场景内的位移与淡入淡出，不是 UI 的 `visible` 切换。
- 键盘仍可用：`Esc` 暂停、`Space/回车` 推进、方向键转头；暂停时界面仍可操作。

## 五、现状与实现取向（2026-10-31 重做后，已实施）

- 控制条、字幕、词条、回答框、卡片、转场与转头提示都经 `SubViewport` 渲染到相机前的世界空间面片，
  主视口不再平铺 `Control`；鼠标点击由相机射线映射回离屏控件，中文输入、回车提交与键盘焦点均保留。
- 面板（控制条、词条、卡片、分支选择、转场、提示）统一随相机移动、固定距离约 1.2 m，不钉死在教室某处：
  任何视角都看得到、点得到，同时保有透视与距离感。自由输入的 `LineEdit` 用 `ViewportTexture`，
  视觉上仍是场景里的牌子，而不是屏幕上的输入框。
- 说话字幕有底板、分行与说话人色；字幕可读优先，前排人物不遮挡文字。
- 观察提示为"观察符号 + 短标签"，悬停展开完整事件名，近距离自动缩小并上移标签。
- 声纹为断续细弧，不再使用粗发光圆环；声源贴住相机时不生成满屏弧线。
- 改造时 `DialogueUI` 的信号与方法签名保持不变（`configure` / `set_subtitle` / `show_chip` /
  `show_choice` / `show_card` / `present_controls` 等），`dialogue_flow.gd` 的时序不动。
- 仍需人工试玩：不同分辨率下的字号、鼠标命中手感与长时间观看的视觉疲劳。

## 六、验收（人工试玩）

1. 在教室里自由转头：控制条、字幕、卡片都产生透视与遮挡变化，没有任何文字贴死在屏幕上；截图里找不到"贴着屏幕四边"的文字。
2. 面板出现时能看出它在玩家前方多远，走过去/转头会改变它与环境的关系。
3. 鼠标点得到每一个按钮；键盘操作照旧。
4. 教室强光/背光下文字仍可读。

## 七、其他既有要求（保留）

1. 发生的、可被观察到的事件，三维空间中要有可以被点击收集起来的小圆球。
   哪些位置必须有球、球的世界坐标与定位规则见 `docs/互动小球与回答框要求-2026-10-31.md`。
2. 说话的字幕直接在说话者的旁边出现。
3. 发出动静的地方要有声纹。
