# 光照、天空与烘焙

## 归属

教室的 Environment、太阳与 LightmapGI 都在 [scenes/classroom_static.tscn](../scenes/classroom_static.tscn) 里，
由布景自己拥有。这样单独打开教室场景（编辑器、预览场景、主场景）都能看到天空，不依赖外层场景。

- 天空：`assets/sky/classroom_sky.tres`（PanoramaSkyMaterial + `je_gray_02_2k.exr`，Poly Haven CC0），
  `energy_multiplier = 2.6`
- 环境光：纯色 `0.97 / 0.98 / 1 × 0.45`。天空环境光在这张 HDRI 上太暗，所以不用 Sky 作为 ambient。
  这个 `ambient_light_energy` 必须真的写进场景：2026-11-01 之前漏写、实际走默认值 `1.0`，
  教室里就变成"环境光平光 + 一版烘焙光"，烘焙的层次完全看不出来（实测环境光 1.0 时把 LightmapGI 的
  `light_data` 清空，画面平均亮度只掉 1.5%；降到 0.2 后烘焙占 39%）。现在正式值是 0.45，
  和 Filmic 色调映射（exposure 1.15）一起把画面拉回白天亮度。
- 太阳：`-38° / 34°`，能量 0.35，`light_bake_mode = Static`（直接光烘进贴图，运行时只照动态物体也就是人物）
- 灯管：`scenes/props/ceiling_light.tscn` 每根带一盏朝下的 `SpotLight3D`
  （`light_bake_mode = Static`、`light_energy = 4.2`、`spot_angle = 78°`、`spot_range = 6.5`、
  `light_size = 0.45`、开阴影），灯管自发光只留 1.4，正上方一块挡光罩（Housing）挡住向上的发射
- LightmapGI：`assets/lightmaps/classroom.lmbake` + `classroom.exr`（512×512 × 6 层，2026-11-01 重烘后从 5 层涨到 6 层）

## 重新烘焙

改了墙、窗、家具位置或灯管之后，烘焙结果就过期了，必须重烘：
改了墙面材质（`assets/materials/wall_plastered.tres` 的 `albedo_color`，或者换了 `albedo_texture`）也算过期：
直射光没问题，但墙自己反弹出去的那部分间接光是按旧颜色烘的，不重烘会偏暗一点点。
`environment_mode = Scene` 烘的是**天空**的辐射，所以换了天空（`assets/sky/classroom_sky.tres`）也要重烘；
反过来 `ambient_light_color` / `ambient_light_energy` 只在运行时生效、不参与烘焙，改它不需要重烘
（2026-11-01 实测：环境光 1.0 与 0.2 各烘一次，产物亮度与体积完全一致）。

1. 在 3D 编辑器里打开 `scenes/classroom_static.tscn`（改了 `classroom_static.tscn` 之后要
   Scene 菜单 **Reload Saved Scene**，否则烘的是标签页里的旧几何）
2. **先补 UV2**：打开 `tools/prepare_lightmap_uv2.gd`，按 Ctrl+Shift+X（File > Run）。
   脚本是带 `@tool` 的 `EditorScript`，打开它脚本编辑器右上角才出现 ▶ 运行按钮；缺 `@tool` 就只是普通脚本，跑不了。
   **正常一次重开场景后的输出**：`675/675 个网格带 UV2`、`本次现场解开 652 个`、
   `环境光能量 = 0.45，与磁盘上的场景一致`，并自动选中 `LightmapGI`
   （数字随几何增减，关键是有"现场解开"、且环境光那句是"与磁盘一致"）。
   环境光自检**不写死数值**，而是拿编辑器内存里的值和磁盘上 `.tscn` 的值比对——
   以后改环境光不用同步改脚本（2026-11-01 就因为写死了 0.20 而误报一次）。
   如果看到 `解开 0 个` 或那句变成"但磁盘上是 xx"、提示"编辑器里是旧场景"，说明标签页里
   还是上次烘完未保存的旧内存态——重开场景再跑，不然这一烘等于白跑。
   这一步不能省：编辑器里家具没有 UV2（见下节），漏了它烘焙只会烘到房间外壳的那 23 个网格。
3. 点 3D 视口顶部工具栏的 **烘焙光照贴图（Bake Lightmaps）**
4. 烘完 **不要保存场景**：第 2 步解开的 UV2 只是内存态，运行时由 `scripts/lightmap_uv2.gd`
   用同一份算法重建；烘焙结果已经直接写进 `assets/lightmaps/`。

当前参数：Quality = High、Bounces = 3、Supersampling = 2×、Denoiser 开、Environment Mode = Scene。

烘焙结果直接写回 `assets/lightmaps/`（`classroom.exr` + `classroom.lmbake` 一起刷新，两个都要提交）。
烘完可以用 `git status` 确认这两个文件确实变了；没变说明烘焙没真正跑完。

## 烘焙后自检

```
Godot_v4.6.1-stable_win64_console.exe --headless --path . --script res://tests/lightmap_check.gd
```

输出 `LIGHTMAP users=665 atlas=512x512 layers=5` + `PASS` 才算烘全：

- `users` 是真正写进贴图的网格实例数——只烘到房间外壳时是 23，整间教室（含家具、窗、幕布）约 665。
  低于 600 通常就是烘焙前漏跑了 `tools/prepare_lightmap_uv2.gd`。
- 同时会校验 `classroom.exr.import` 的 `slices/vertical` 与贴图实际层数一致。
  层数是烘焙挑的（现在 6），几何变了可能涨到 7 层：烘焙后编辑器会自动把这一行改掉，
  `git diff` 里能看到 `.import` 跟着变，**要和新贴图一起提交**。

## UV2 从哪来

LightmapGI 只能烘有第二套 UV 的网格，没有 UV2 的网格会被直接跳过（不报错，只是烘不到）：

- 房间外壳（墙、地、天花、窗洞、踢脚、讲台、横梁）的 UV2 已经写进场景，是烘焙时生成的 `ArrayMesh` 子资源，
  所以它们任何时候都能参与烘焙，共 23 个网格。
- 家具、窗、门、灯管、幕布是实例化的子场景，源文件里还是 `PrimitiveMesh`，**编辑器里不会自动补 UV2**：
  `scripts/classroom.gd` 不是 `@tool`，`LightmapUV2.prepare()` 只在运行时 `_ready()` 跑。
  所以在编辑器里要先手动跑 `tools/prepare_lightmap_uv2.gd`（实测 675 个网格、约 150 个唯一网格，耗时不到 1 秒）。
- 两边调的是同一个 `prepare()`：把 `PrimitiveMesh` 转成 `ArrayMesh`、调 `lightmap_unwrap()`、
  设 `gi_mode = Static`。UV 布局因此一致；代价是运行时加载多约 0.7 秒。
- 2026-10-23 那次烘焙没跑这一步，贴图里只有外壳 23 个网格：家具一直没吃到烘焙阴影，
  2026-11-01 新加的投影幕布更是只有环境光，看起来发平发冷就是这个原因。
- 如果以后把家具也烘进场景，记得两边跑的是同一份代码，否则 UV2 对不上、光照会错位。

## 灯与材质（2026-11-01 重做）

原来的教室**没有任何真正的灯**：`ceiling_light.tscn` 里只有一块 `emission_energy_multiplier = 5.0` 的发光盒子。
自发光确实会参与烘焙（文档里明确说可以拿它当面光源），但它是**四面八方的漫发射**：灯管离天花板 0.35 m、
离桌面 2 m 以上，平方反比下天花板拿到约 40 倍辐照。实测"烘焙开 − 关"的逐格亮度差：天花板区 +0.44、
桌面区 +0.09、近处地板 +0.01 —— 光几乎全打在天花板和墙上，桌子和人物是黑的。

改法（A）：

- 每根灯管加一盏朝下的 `SpotLight3D`（`light_bake_mode = Static`）。Static 表示直接光和间接光都烘进贴图，
  运行时不再照静态表面，但**仍然照亮动态物体**——人物正是靠它才有光。
- 灯管自发光降到 1.4（只保留"看着在亮"），上方加一块挡光罩 `Housing` 挡住向上的发射。
- `light_energy` 是唯一主要旋钮：现在 5.0。偏暗/偏亮只调这一个数，改完要重烘。
- 担心性能：9 盏带实时阴影实测 7.4 ms/帧，关掉 `shadow_enabled` 是 3.4 ms（Compatibility、1280×720）。
  烘焙阴影已经在贴图里，运行时关掉阴影只影响人物投的影子。

改法（B）：

- `albedo_color` 超过 1 在物理上不成立（等于反射得比照进来的还多），任何光都会被放大并顶到过曝。
  2026-11-01 把 `wall_plastered.tres` 从 `1.38 / 1.50 / 1.70` 降到 `0.95 / 0.98 / 1.00`。
- 天花板单独拆出 `ceiling_plastered.tres`：它离灯最近，最容易被推到全白，
  而且在 `classroom_static.tscn` 里用 `material_override` 单独覆盖 `Room/Ceiling`，地板不受影响。
- 当时的取值（墙 `0.95 / 0.98 / 1.00`、顶 `0.88 / 0.91 / 0.94`）已在第二轮改掉：
  真正的米黄来自贴图本身，材质这条路已经走到头，见下一节。
- 原则不变：**别再把 albedo 顶回 1 以上**，现在两个材质都是 ≤1 的中性值。

## 墙色与画面亮度（2026-11-01 第二轮）

第一轮把 albedo 顶回 1 以下之后，画面变成"墙米黄 + 整体偏暗"，根因有三个，分头处理：

**1. 贴图本身偏暖偏暗（米黄的真正来源）。** `plastered_wall_diff_1k.jpg` 的 sRGB 均值只有
`0.691 / 0.659 / 0.613`——它就是一张暖灰偏黄的贴图；`albedo_color` 又卡在 ≤1 不能再往上乘，
所以只在材质里调永远调不白。做法是**另存一版中性化贴图** `plastered_wall_diff_neutral_1k.jpg`：

- 逐通道 `v^0.72 × gain`（gain 取 `1.15 / 1.19 / 1.27`，按原图暖调反过来补），
  `v > 0.93` 处以 0.28 斜率软压缩，避免高光被裁成死白块。
- 均值变成 `0.880 / 0.879 / 0.891`，中性微冷，纹理细节保留。
- 原图留在仓库里没删；`wall_plastered.tres` 与 `ceiling_plastered.tres` 都改指向新图。
- 生成脚本只在本地跑过（`.local/wall_tex_fix.gd`，不提交）；要复现就照上面两个数重跑一次。

**2. 没有色调映射，亮部直接切白。** `Environment_classroom` 过去是默认的 `Linear`，
灯管、窗口、桌面上的纸一到 1.0 就成纯白片，这正是"漫反射看着假"的一半原因。现在改成 `Filmic`、
`tonemap_exposure = 1.15`：高光有滚降、暗部有抬起，过渡像照片而不像未处理的渲染。
在 Compatibility 下实测生效（对比 Linear 的画面差异 0.093，不是空设置）。

**3. 环境光太低 + SSAO 过强。** `ambient_light_energy` 从 0.2 提到 0.45，色温改 `0.97 / 0.98 / 1`；
`ssao_intensity` 从 2.2 降到 1.0、半径 1.6 → 1.2，并加 `ssao_light_affect = 0.15` 让接触阴影参与直射光。
SSAO 2.2 那档把桌椅下方压成死黑，看起来像漏光而不是阴影。

同时开了 `glow`（intensity 0.45 / bloom 0.08 / softlight、阈值 1.0），灯管才有"在发光"的边缘，
而不是贴上去的白条。Compatibility 下确认生效（关掉 glow 画面差异 0.012）。

实测同一组机位平均亮度：`0.236 / 0.263 / 0.271` → `0.429 / 0.469 / 0.502`（A/B/C 机位），
墙的米黄基本消失。

**这四条都不需要重烘**：环境光、色调映射、glow、SSAO 是运行时后处理；
贴图虽然进了烘焙，但换的是 albedo，不是光照几何，重烘只是让它更准。

## 灯的配光（2026-11-01 第二轮，**待重烘**）

原来的聚光灯 `spot_range = 4.2` 其实**够不到墙**：灯在 `y = 3.35`，到最远的墙斜距超过 6 m，
到近侧墙中部也有 2.6 m 以上。结果只有灯正下方一圈被照到，墙和天花板全靠环境光"提亮"——
这就是"整体打得很平、没有真实漫反射"的结构原因。

改成宽配光：

| 参数 | 旧 | 新 | 理由 |
| --- | --- | --- | --- |
| `spot_range` | 4.2 | 6.5 | 让光真正打到墙面与远处桌面 |
| `spot_angle` | 72 | 78 | 略宽，减少明显的光锥边 |
| `spot_angle_attenuation` | 0.6 | 0.55 | 锥内分布更均匀，边缘收得柔 |
| `light_size` | 0.12 | 0.45 | 近似灯管长度，半影更软 |
| `light_color` | `1 / 0.97 / 0.92` | `1 / 0.98 / 0.95` | 原来的暖黄会把天花板染成土黄 |
| `light_energy` | 5.0 | 4.2 | 覆盖变大后略降，避免墙面过曝 |

**这组参数还没烘焙**，`.exr` 仍是上一轮（range 4.2）的结果，所以现在墙上的明暗分布还是老的。
重烘之后墙会有自下而上的渐变、天花板会吃到更多反射光。

`assets/sky/classroom_sky.tres` 的 `energy_multiplier` 也从 2.0 提到 2.6（窗外更亮一点）。
天空参与烘焙（`LightmapGI.environment_mode = Scene`），所以和灯的改动一起重烘。

## 角色反照率（2026-11-01 第二轮）

烘焙换成宽配光后，静态面亮了，**人物却比墙面更白**——因为人物是动态网格，进不了光照贴图，
只能吃 9 盏 Static 聚光灯的实时直射，而 9 盏灯的直射是线性累加的，没有真实世界的曝光适应。
结果是皮肤、白衬衫、袜子在灯正下方顶到接近纯白，颜色信息全丢，人物看起来像个白模。

Quaternius 的角色材质是纯色、没有贴图（皮肤 `#cead86`、白 `#b4b4b4`），本身数值并不高，
过曝完全来自照度，所以压 albedo 是**补偿**而不是根治。根治要降 `light_energy` 再重烘一遍，
代价是静态面一起吃暗；这一轮选了补偿。

做法是 `scripts/actor_shading.gd`（`ActorShading.dim()`）：

- 在 `character_pose.gd::_ready()` 里、`_apply_outfit()` **之后**调用——outfit 会复制出独立的
  override 材质，压暗必须落在最终生效的那一份上。`teacher_animator` 继承 `character_pose`，
  老师因此自动覆盖。
- 用材质上的 `actor_albedo_dim` meta 去重：同一份材质被几十个角色实例共享，
  不去重会重复相乘、越乘越黑。
- 只改内存里的导入材质，不动 `.glb` 源文件。

系数扫过 `0.60 / 0.42 / 0.28 / 0.16`：0.60 和 0.42 皮肤仍然发白、衣服分不出颜色；
0.16 开始像欠曝、暗部丢细节；**0.28 皮肤回到肉色且有明暗层次**，最终取 `ALBEDO_DIM = 0.30`。

顺带把 `PropKit` 的纸张颜色从课本 `0.95/0.94/0.89`、本子 `0.96/0.96/0.93` 统一压到
`PAPER_COLOR = 0.84/0.83/0.78`（真实书纸白度约 0.8）。原来那两档在灯直射下整片顶白，
看不出纸和桌面的反差。

## 已知限制

- 改布局不重烘，光照会和几何对不上（比如墙挪了、光斑还在原处）。
- 人物是动态骨骼网格，**进不了光照贴图**：它只吃 9 盏 Static 聚光灯的实时直射光 + LightmapGI 生成的
  光照探针提供的间接光。所以人物身上的明暗永远比桌面"干净"一点，这是技术边界，不是漏光。
- 2026-11-01 已按上面的流程重烘：贴图里有 665 个网格（家具、窗、门、灯管、幕布全进了），
  只剩隐藏的 `StageFloor` 被跳过；同一天把环境光从默认 `1.0` 降到 `0.2`，烘焙才成为主光
  （实测占画面亮度约 39%，改前只有 1.5%）。第二轮把环境光提到 `0.45`、换成 Filmic 色调映射，
  平均亮度从 0.24 回到 0.50——**环境光和色调映射是纯运行时参数，改了不用重烘**。
- 人物、本子、白衣服这类高反照率物体在灯正下方仍会顶到接近纯白：9 盏灯的直射是线性累加的，
  没有真实世界的曝光适应。已用 `ActorShading.dim()`（0.30）与 `PropKit.PAPER_COLOR` 压过一轮，
  但这是补偿——改灯的能量才是根治，代价是静态面跟着变暗、要重烘。
- `ActorShading.ALBEDO_DIM` 是全局一刀切：离灯远的角色（讲台、后排角落）会比灯下的角色更暗，
  这是"减法"方案的天花板。要按位置自动补偿得接 auto exposure 或逐角色调，目前没做。

## 开发期的临时处理

开发中改了布局又不想重烘时，有两个选择：

1. **接受错位**：光斑会留在老位置，改得少的时候不明显，改得多就别扭。
2. **临时关掉烘焙**：选中 `LightmapGI`，把 `Light Data` 清空（或直接把节点 Visible 关掉），
   然后把实时灯调回来——太阳 `light_energy ≈ 2.2`、Environment 的 `ambient_light_energy ≈ 1.0`、
   两盏 WindowBounce 回 `0.9`。这样回到"实时平光"，能继续开发，只是没有烘焙的柔和感。
   注意 `1.0` 只属于这种开发期兜底状态，正式跑的教室是 `0.45`（2026-11-01 第二轮定的）。

最终交付前记得走一遍正常的烘焙流程，把这两处改动还原。
