# 光照、天空与烘焙

## 归属

教室的 Environment、太阳与 LightmapGI 都在 [scenes/classroom_static.tscn](../scenes/classroom_static.tscn) 里，
由布景自己拥有。这样单独打开教室场景（编辑器、预览场景、主场景）都能看到天空，不依赖外层场景。

- 天空：`assets/sky/classroom_sky.tres`（PanoramaSkyMaterial + `je_gray_02_2k.exr`，Poly Haven CC0）
- 环境光：纯色 `0.95 / 0.96 / 1 × 0.2`。天空环境光在这张 HDRI 上太暗，所以不用 Sky 作为 ambient。
- 太阳：`-38° / 34°`，能量 0.35（只给将来的动态物体补一点，教室本身由烘焙光照亮）
- LightmapGI：`assets/lightmaps/classroom.lmbake` + `classroom.exr`（512×512 × 5 层）

## 重新烘焙

改了墙、窗、家具位置或灯管之后，烘焙结果就过期了，必须重烘：

1. 打开 `scenes/classroom_static.tscn`
2. 选中 `LightmapGI` 节点（工具栏的烘焙按钮只有选中它才出现）
3. 点 3D 视口顶部工具栏的 **烘焙光照贴图（Bake Lightmaps）**

当前参数：Quality = High、Bounces = 3、Supersampling = 2×、Denoiser 开、Environment Mode = Scene。

烘焙结果直接写回 `assets/lightmaps/`，不需要手动保存资源；场景保存与否不影响烘焙结果。

## UV2 从哪来

LightmapGI 只能烘有第二套 UV 的网格：

- 房间外壳（墙、地、天花、窗洞、踢脚）的 UV2 已经写进场景，是烘焙时生成的 `ArrayMesh` 子资源。
- 家具、窗、门、灯这些实例化子场景没有改源文件，运行时由 `scripts/lightmap_uv2.gd` 在现场补 UV2：
  把 `PrimitiveMesh` 转成 `ArrayMesh`、调 `lightmap_unwrap()`、设 `gi_mode = Static`。
  这段代码和烘焙前编辑器里跑的是同一段，UV 布局一致；代价是加载时多约 0.3 秒。
- 如果以后把家具也烘进场景，记得两边跑的是同一份代码，否则 UV2 对不上、光照会错位。

## 已知限制

- 全静态：教室没有动态物体，所以实时灯光被压到接近 0。以后加会动的人物，要单独给它们补灯，否则只有环境光。
- 灯管：`ceiling_light.tscn` 的自发光强度是 5.0，只有烘焙时它会照亮别的东西；运行时它只是自己亮。
- 改布局不重烘，光照会和几何对不上（比如墙挪了、光斑还在原处）。

## 开发期的临时处理

开发中改了布局又不想重烘时，有两个选择：

1. **接受错位**：光斑会留在老位置，改得少的时候不明显，改得多就别扭。
2. **临时关掉烘焙**：选中 `LightmapGI`，把 `Light Data` 清空（或直接把节点 Visible 关掉），
   然后把实时灯调回来——太阳 `light_energy ≈ 2.2`、Environment 的 `ambient_light_energy ≈ 1.0`、
   两盏 WindowBounce 回 `0.9`。这样回到"实时平光"，能继续开发，只是没有烘焙的柔和感。

最终交付前记得走一遍正常的烘焙流程，把这两处改动还原。
